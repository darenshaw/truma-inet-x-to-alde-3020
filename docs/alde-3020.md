# Alde Compact 3020 behind a Truma iNet X panel

This build adds support for an **Alde Compact 3020** (measured on a 3020 HE) connected to a
**Truma iNet X panel**. This page lists every entity it creates on that setup and what each
one does. The Truma Combi entities from upstream are described in [entities](entities.md).

Measured on: iNet X Panel SW 3.5.38 / HW 3.4, Alde Compact 3020 HE, 2026-10-02.

## Install

HACS → ⋮ → **Custom repositories** → add
`https://github.com/darenshaw/truma-inet-x-to-alde-3020` with category **Integration**.
Install **Truma iNet X (Alde 3020)**, then restart Home Assistant. Pairing works exactly
as in the [README](../README.md#pair).

If the upstream integration (`rpodgorny/hass-truma-inetx`) is installed, remove it from
HACS first. Both use the same folder, `custom_components/truma_inetx`.

## How the system looks to Home Assistant

The panel is a gateway onto a bus. Home Assistant creates one device for each thing on the
bus that reports something:

| Device | Bus address | What it is |
|---|---|---|
| **Truma iNet X panel** (named after the panel, e.g. *Truma iNetX-AC4C1E*) | `0x0101` | The control panel itself: display, timers, faults, the room-climate mode |
| **Alde Compact 3020 HE** | `0x0404` | The heater: setpoint, energy sources, hot water, its temperatures |
| **Bluetooth management** | `0x0601` | The panel's Bluetooth bonding: slots and connection state (diagnostic only) |

There is no `0x0201`, the address a Truma Combi uses. Every command for the heater goes
to the Alde at `0x0404`.

## Alde Compact 3020 HE

### Controls

| Entity | Type | What it does |
|---|---|---|
| **Alde Compact 3020 HE** | Thermostat (`climate`) | **The heating control.** Modes: *Off* and *Heat*. The target can be set from 5 to 30 °C in 1 °C steps, and the reading shown is the room temperature. The target is written to the Alde's own setpoint, which is what it regulates to (see [Setting the temperature](#setting-the-temperature)). |
| **Electric heating** | Select | The Alde's 230 V element: *off*, *1 kW*, *2 kW*, *3 kW*. |
| **Gas** | Switch | Enables or disables gas as an energy source. |
| **Energy source priority** | Select | *Electric* or *Gas*: which source the Alde uses first when both are enabled. |
| **Hot water** | Switch | Hot water on or off. The Alde has no temperature steps for hot water, so this is a switch rather than the Combi's Eco/Comfort/Hot select. |
| **Water boost** | Switch | Hot-water boost on or off. |

At least one energy source (electric or gas) must be on for the Alde to heat. With both
off, it goes to *idle* in Heat mode.

### Readings

| Entity | Type | What it shows |
|---|---|---|
| **Room temperature** | Sensor, °C | The room temperature as the Alde measures it. |
| **Outside temperature** | Sensor, °C | The Alde's outdoor sensor. |
| **Air heating active** | Binary sensor | *On* while the Alde is heating right now. *Off* when it is off **or idle** at temperature. |
| **Fault** | Binary sensor | *On* while the Alde reports a fault. |
| **Fault code** | Sensor (diagnostic) | The code of the current fault. *Unknown* means there is no fault. |
| **Requesting energy** | Binary sensor (diagnostic) | *On* when the Alde needs an energy source and has none enabled. |
| **Power mode (raw)** | Sensor (diagnostic) | The Alde's power-management mode as a raw number (3 seen so far). The meaning is not documented. |

## Truma iNet X panel

### Controls

| Entity | Type | What it does |
|---|---|---|
| **Timer 1**, **Timer 2**, **Timer 5** … | Switch | Turns each of the panel's configured heating timers on or off. Only configured slots appear. The timer's name, start, end and weekdays are attributes of the switch. |
| **Display brightness** | Number (config) | Panel brightness, 10–100 %. |
| **Night brightness** | Number (config) | Panel brightness at night, 1–10. |
| **Display timeout** | Number (config) | Seconds of inactivity before the display dims. |
| **Screensaver** | Switch (config) | The panel's screensaver on or off. |

### Readings

| Entity | Type | What it shows |
|---|---|---|
| **BLE connection** | Binary sensor | Whether Home Assistant is in touch with the panel. With a poll interval set, it stays *on* between polls. |
| **Heating** | Binary sensor | The panel's own heating flag (`System.FlameStatus`). It is not the Alde's: use **Air heating active** for that. |
| **Heating status** | Sensor (diagnostic) | The same flag by name: *off*, *running*, *idle*. |
| **Shore power** | Binary sensor | The panel's "plugged in" flag. It does **not** show whether the Alde's 230 V element has power: the 2 kW element heated while this read *off*. |
| **Timer 1 schedule** … | Sensor | When each timer starts. The rest of the timer is in the attributes. |
| **Timers enabled** | Sensor (diagnostic) | How many timers are switched on. |
| **Fault** / **Fault code** | Binary sensor / sensor (diagnostic) | The panel's own fault, as on the Alde. |
| **Panel clock** | Sensor (diagnostic) | The panel's date and time. |
| **Climate state (raw)** | Sensor (diagnostic) | `RoomClimate.Active` as a number: 0 off, 2 heating, 4 heating with the heater idle (as seen in testing). |
| **Power mode (raw)** | Sensor (diagnostic) | The panel's power-management mode as a raw number. |
| **Internal temperature** | Sensor, disabled by default | The panel's own temperature reading. |
| **Supply voltage** / **Logic supply** | Sensor, disabled by default | The panel's 12 V and 5 V supply. |
| **Temperature source (raw)**, **Time since last touched** | Sensor (diagnostic), disabled by default | Internal panel values, for diagnostics. |

## Bluetooth management (diagnostic)

| Entity | What it shows |
|---|---|
| **Free slots** | How many more Bluetooth bonds the panel can accept. If this reaches 0, a new phone or Home Assistant cannot pair. |
| **Connection state** / **State** | Raw state of the panel's Bluetooth management. |

## Setting the temperature

The Alde and the panel each keep their own target temperature:

- the **Alde's** target (`AirHeating.TgtTemp`), which the thermostat entity sets
- the **panel's** room target (`RoomClimate.TgtTemp`, e.g. 22 °C)

Measured with the panel in *Heat*, its target at 22 °C, the room at 15.6 °C and electric heating at 2 kW:

| Alde target | Alde |
|---|---|
| 17 °C | **heating** |
| 14 °C (below the room) | **idle within 6 s**, although the panel still said 22 °C |

So **the Alde regulates to its own target, which is the one the thermostat entity sets.**
Changing either target does not move the other, and switching to *Heat* does not copy the
panel's value to the Alde.

To heat:
1. Set the target on the thermostat.
2. Enable an energy source (electric and/or gas).
3. Set the mode to *Heat*.

## Connection

- **Keep-alive:** the panel only sends something when a value changes. A quiet panel used
  to trip the integration's 90 s stall watchdog and drop a healthy link every 90 s. A link
  that has been quiet for 45 s is now sent a small request, and the panel acknowledging it
  keeps the link up.
- **Sharing with the Truma app:** the panel has a limited number of connections. To leave
  it free for the Truma app on a phone, set a **poll interval** under Settings → Devices &
  Services → Truma iNet X → **Configure**. At 60 s, Home Assistant connects, reads for about
  30 s and disconnects. Changes made at the panel then show up in Home Assistant within about
  90 s. Commands from Home Assistant still connect and send straight away. Set it to 0 to
  stay connected.

## Not exposed

The panel also reports parameters that get no entity, on purpose:

- factory reset, pairing search/delete, the beep pattern
- install and firmware records, certificate IDs
- the panel's copy of the outside temperature (`Temperature.External`), which duplicates the Alde's sensor
- `AirHeating.Location`, whose meaning is not known (it reads 1)
- the panel's room target (`RoomClimate.TgtTemp`), because it does not control the Alde (see above)

They can all be seen in a diagnostics download (⋮ → **Download diagnostics** on the device page).
